# BLACK GOLD GAMES — دليل التشغيل والنشر

منصة عربية RTL بهوية سوداء وذهبية مبنية باستخدام React + TypeScript + Vite وSupabase. تتضمن واجهة رئيسية متجاوبة، تسجيل حسابات عبر Supabase Auth، إنشاء غرف ورموز دعوة، دردشة الغرفة، ومخططًا خادميًا للعبة إكس أو. الألعاب الأخرى موجودة في الواجهة كبطاقات وغرف، لكن محركاتها التنافسية ليست مكتملة في هذه النسخة؛ لا تعتبرها ألعابًا جاهزة للتصنيف أو المكافآت.

## مهم قبل النشر
هذا الأرشيف لا يتصل تلقائيًا بخدمة خارجية. لا يمكن إنشاء مشروع Supabase أو Netlify نيابةً عنك من داخل الملفات. بعد إعداد مشروع Supabase وتنفيذ SQL وإضافة مفاتيح البيئة، تعمل المصادقة والغرف وميزات إكس أو وفق القيود الموضحة هنا. لا ترفع أي مفتاح `service_role` إلى المتصفح أو Git.

## 1) إنشاء Supabase
1. أنشئ مشروعًا جديدًا في لوحة Supabase الرسمية: https://supabase.com/dashboard
2. من **SQL Editor** افتح `supabase/schema.sql` والصق محتواه وشغّله على مشروع جديد.
3. من **Project Settings → API** انسخ Project URL ومفتاح `anon`/publishable فقط.
4. في **Authentication → URL Configuration** أضف رابط موقعك المنشور إلى Site URL وRedirect URLs. أضف أيضًا `http://localhost:5173/**` للتطوير.
5. راجع إعداد تأكيد البريد الإلكتروني. عند تفعيله، على المستخدم تأكيد البريد قبل تسجيل الدخول.
6. تأكد من تفعيل Realtime للجداول التي أضافها SQL: `room_members`, `matches`, `room_messages`.
7. أنشئ حسابك أولًا، ثم لمنح حساب إدارة: خذ UUID من `Authentication → Users` ونفّذ يدويًا:
   ```sql
   insert into public.admin_users(user_id) values ('UUID-OF-YOUR-ACCOUNT');
   ```
   لا توجد واجهة إدارة كاملة في هذه النسخة، ولا تجعل إدخال حسابات الإدارة متاحًا للعامة.

## 2) التشغيل المحلي
يتطلب Node.js 20 أو أحدث.
```bash
cp .env.example .env
# ضع القيم الصحيحة داخل .env
npm install
npm run dev
```
افتح العنوان الذي يعرضه Vite. لإنشاء نسخة إنتاج:
```bash
npm run build
npm run preview
```

## 3) النشر على Netlify
1. ارفع المجلد إلى مستودع Git، ثم أنشئ موقعًا جديدًا في Netlify واربط المستودع. هذا أفضل من رفع ZIP يدويًا لأن Netlify يحتاج إلى تثبيت الحزم وبناء `dist`.
2. Build command: `npm run build`
3. Publish directory: `dist`
4. أضف متغيري البيئة في **Site configuration → Environment variables**:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. أعد النشر بعد إضافة المتغيرات.
6. أضف رابط Netlify في Supabase Authentication URL Configuration. روابط `/room/ABC123` تعود إلى تطبيق SPA بفضل `netlify.toml`.

## 4) مشاركة الغرف
سجّل الدخول، أنشئ غرفة، ثم انسخ رابط `/room/CODE` وأرسله. يجب أن يكون المستخدم مدخلًا لحسابه. رمز الغرفة يعمل بمثابة سر دعوة للغرفة الخاصة؛ لا ترسله علنًا إذا أردت إبقاءها خاصة.

## ما الذي يعمل وما الذي لم يكتمل؟
### متاح بعد ربط Supabase
- واجهة عربية متجاوبة.
- تسجيل وإنشاء حساب عبر Supabase Auth وحفظ الجلسة.
- إنشاء غرفة برمز، والانضمام برمز، وعرض الأعضاء، وتغيير حالة الاستعداد.
- دردشة نصية داخل الغرفة مع تحقق عضوية الغرفة وقيود طول الرسالة.
- بداية محرك إكس أو خادمي: ترتيب الدور، منع تكرار الخانة، كشف الفوز والتعادل، وتحديث نتيجة أساسية.
- مخطط قاعدة البيانات وسياسات RLS الأساسية.

### غير مكتمل / لا تعتبره جاهزًا
- مزاد الأسئلة ومداقش وصراع الكلمات: واجهات فقط حاليًا؛ لا توجد محركات جولات مكتملة.
- لعبة إكس أو تحتاج اختبارًا تكامليًا فعليًا على مشروع Supabase جديد. النسخة الحالية لا تدّعي نجاح اختبار جهازين بعد النشر.
- لا توجد لوحة إدارة متكاملة، ولا نظام صداقة وإشعارات مكتمل، ولا نظام موسمي أو anti-cheat متقدم.
- الدردشة لا تطبق حاليًا حد معدل قويًا على الخادم أو كتمًا/إبلاغًا متكاملًا.
- إظهار بيانات المتصدرين والإنجازات في الواجهة غير موصول بالكامل.
- روابط الدعوة ليست مصادقة بحد ذاتها؛ الغرفة الخاصة تتطلب رمزها، لكن النظام الحالي لا يطبق دعوات موقعة منفصلة أو قائمة سماح بالأصدقاء.
- لا يوجد اختبار أمني مستقل أو تدقيق RLS احترافي.

## الأمان
- المفتاح الموجود في المتصفح يجب أن يكون anon/publishable فقط، مع RLS.
- لا تضف `service_role` إلى `.env` الخاص بالواجهة أو أي متغير يبدأ بـ `VITE_`.
- راجع SQL وسياسات RLS قبل إطلاق عام؛ المخطط أساس تطوير وليس شهادة تدقيق أمني.
- أضف rate limiting ومراجعة إساءة الاستخدام قبل السماح باستخدام عام واسع.
- لا تعتمد على أرقام الواجهة؛ النتائج الموثوقة يجب أن تأتي من RPC/قاعدة البيانات.
